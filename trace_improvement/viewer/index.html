PoC of TRACE Stage 1 on MAVREC

This page is part of a replication of the TRACE paper. Stage 1 of TRACE, applied here to the MAVREC drone dataset, requires pairs of videos showing the same scene from different camera viewpoints, together with the tracked object's bounding box in both views. Since each real scene is recorded from only a single viewpoint, a second viewpoint is synthesized using camera-controlled video generation models. Video 1 is the original drone footage used as input for all experiments below.

The first model evaluated was ReCamMaster, a model designed for camera-controlled video re-rendering. Video 2 shows its output after rotating the camera by approximately 20°. Although the rendered video appears realistic initially, later frames contain a building in the upper-right corner that is absent from the original footage. To test whether this was caused by the magnitude of the viewpoint change, the same experiment was repeated with a smaller 10° rotation (Video 3). The artifacts remained, with the model introducing a new structure near the horizon and altering the appearance of the sky. Since these regions are not visible in the original video, the generated content cannot be verified from the input observations.

To understand how these artifacts would affect later stages of the pipeline, the ReCamMaster output was carried through the rest of the pipeline. Video 6 shows CoTracker point tracks over the rendered video, and Video 7 shows the tracked object's bounding box transferred using those tracks. This illustrates how Stage 2 would operate if Stage 1 re-rendering were generated by ReCamMaster.

TrajectoryCrafter was evaluated next, following a different approach. Rather than synthesizing every frame directly, it first estimates scene geometry and projects pixels from the original video into the target viewpoint, using a generative model only to complete regions that become newly visible after reprojection.

Video 4 repeats the same 10° rotation used in Video 3. Unlike ReCamMaster, the rendered scene preserves the appearance of the sky and surrounding structures. Video 5 applies a larger combined pan and tilt to evaluate a more challenging camera motion, while Video 8 evaluates forward camera translation. In Video 8, nearby objects such as the roadside sign exhibit larger apparent motion than distant trees, consistent with the depth-dependent parallax expected from forward camera movement.

Part 4. Training-free editing test

Stage 2 of TRACE is normally a fine-tuned model that erases an object and redraws it along a new path. This is a training-free baseline of the same idea, using only classical computer vision on Video 4: the real DEVA box marks where to cut the object out, a classical inpainting method fills the hole left behind, and the cut-out object is pasted back along a different, hand-chosen path instead of its real one. No diffusion model and no training are involved. It is a rough test of whether the erase-and-replace idea looks plausible at all, not a finished editing method. Videos 15 and 16 use plain classical methods and show two clear problems: a visible ghost mark where the object used to be, and a blurry, hard-edged paste. Videos 17 and 18 fix both, swapping in a real pretrained inpainting model (LaMa) for the erase step and blending the pasted object into the background instead of overwriting pixels flatly.

Part 5. Inserting a new object

So far the edits only moved an object that was already in the scene. This tests something different: adding an object that was never there. A real pedestrian, cropped from the original 4K footage where two people are genuinely visible walking on a park path, is placed onto the TrajectoryCrafter render (Video 4) along that same path, using real frames of them walking so their legs actually move instead of sliding as a static cutout. No synthetic or generated person is used, only their placement in this shot is fabricated. Scaled larger than true aerial size would allow, since a photo-accurate person here would only be a few pixels tall.

Video 19

A real walking person inserted onto the park path in Video 4, marked with a red circle since they are small and easy to miss. Blended in with the same method as Video 18. This attempt did not read as a recognizable person at this scale, see Part 6 for a better approach.

Part 6. Object insertion with a real diffusion model

AnyDoor is a published zero-shot model for inserting a reference object into a target scene without training on our specific object or scene. The same person crop used in Video 19 is inserted here instead using AnyDoor, frame by frame, then blended in to remove a border artifact from the raw model output. This produces a more recognizable person shape when viewed closely than the plain pixel paste in Video 19, though the person is still small and easy to miss at normal video scale.
